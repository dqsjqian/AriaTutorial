# 测试：怎么验证响应式代码是对的

前面 18 章都在讲"怎么写"。这一章回答一个更实际的问题：**我怎么知道写对了？** 🧪

好消息是，Aria 的 ViewModel 是纯 C++ 类 —— **不需要窗口、不需要事件循环、不需要 UI 工具包**。所以绝大部分逻辑可以在命令行下测完。

---

## 📄 完整程序

```cpp
// ch19: 测试 -- ViewModel 是纯 C++, 测试不需要界面
//
// 这一章回答一个问题: 我怎么知道自己的响应式代码是对的?
// 核心优势在于: Aria 的 ViewModel 不依赖任何 UI 工具包, 所以
// 绝大部分逻辑可以在没有窗口、没有事件循环的情况下测完。
#include "aria/aria.hpp"
#include "aria/async/executor.hpp"
#include "aria/async/task.hpp"

#include <iostream>
#include <string>

using namespace aria;
using namespace aria::async;

// ---------------------------------------------------------------------------
// 被测对象: 登录表单
// ---------------------------------------------------------------------------
struct LoginViewModel {
    Property<std::string> user{""};
    Property<std::string> password{""};
    Property<int>         attempts{0};

    Computed<bool> can_submit{[&] {
        return !user.get().empty() && password.get().size() >= 6;
    }};

    Computed<std::string> hint{[&] {
        if (attempts.get() >= 3) return std::string("尝试次数过多");
        if (user.get().empty())   return std::string("请输入用户名");
        if (password.get().size() < 6) return std::string("密码至少 6 位");
        return std::string("可以提交");
    }};
};

// ---------------------------------------------------------------------------
// 极简断言: 教程里够用, 真实项目请用 doctest / Catch2 / GoogleTest
// ---------------------------------------------------------------------------
static int failures = 0;

static void check(bool ok, const char* what) {
    std::cout << (ok ? "   [ok]   " : "   [FAIL] ") << what << '\n';
    if (!ok) {
        ++failures;
    }
}

int main() {
    std::cout << "== 1. 纯逻辑: 没有窗口也能测 ==\n";
    {
        LoginViewModel vm;
        check(!vm.can_submit.get(), "空表单不能提交");

        vm.user = "aria";
        check(!vm.can_submit.get(), "只填用户名仍不能提交");

        vm.password = "12345";
        check(!vm.can_submit.get(), "密码 5 位不能提交");

        vm.password = "123456";
        check(vm.can_submit.get(), "用户名 + 6 位密码可以提交");

        check(vm.hint.get() == "可以提交", "提示文案随状态更新");
    }

    std::cout << "\n== 2. 派生的提示文案覆盖每条分支 ==\n";
    {
        LoginViewModel vm;
        check(vm.hint.get() == "请输入用户名", "空用户名 -> 提示输入用户名");

        vm.user = "aria";
        check(vm.hint.get() == "密码至少 6 位", "密码太短 -> 提示密码长度");

        vm.attempts = 3;
        check(vm.hint.get() == "尝试次数过多", "超过次数 -> 优先级最高的提示");
    }

    std::cout << "\n== 3. 订阅行为: 只在该通知的时候通知 ==\n";
    {
        Property<int> value{0};
        int notifications = 0;
        auto sub = value.on_changed([&](const int&) { ++notifications; });

        value = 1;
        value = 1;              // 等值写入, 不通知
        value = 2;
        check(notifications == 2, "等值写入被静默丢弃");

        sub.release();
        value = 3;
        check(notifications == 2, "退订后不再收到通知");
    }

    std::cout << "\n== 4. 批量修改只产生一次通知 ==\n";
    {
        Property<int> a{0};
        int notifications = 0;
        auto sub = a.on_changed([&](const int&) { ++notifications; });

        aria::batch([&] {
            a = 1;
            a = 2;
            a = 3;
        });
        check(notifications == 1, "batch 内三次写入只推一次");
    }

    std::cout << "\n== 5. 异步逻辑: blocking_get 把协程结果取出来 ==\n";
    {
        auto task = []() -> Task<int> {
            co_return 6 * 7;
        };

        check(task().blocking_get() == 42, "协程结果可以被同步取出");
    }

    std::cout << "\n== 6. 框架自带的一致性套件 ==\n";
    std::cout << "   自定义适配器可以拿框架的套件自查:\n";
    std::cout << "     aria/binding/testing/adapter_conformance.hpp\n";
    std::cout << "   自定义列表源可以跑:\n";
    std::cout << "     aria/testing/list_conformance.hpp\n";
    std::cout << "   这两套是内置适配器和内置列表视图自己也在跑的同一份测试。\n";

    std::cout << "\n------------------------------\n";
    if (failures == 0) {
        std::cout << "全部通过\n";
    } else {
        std::cout << failures << " 项失败\n";
    }
    return failures == 0 ? 0 : 1;
}
```

## 1️⃣ 被测对象是一个普通 struct

```cpp
struct LoginViewModel {
    Property<std::string> user{""};
    Property<std::string> password{""};
    Property<int>         attempts{0};

    Computed<bool> can_submit{[&] { ... }};
    Computed<std::string> hint{[&] { ... }};
};
```

注意它**没有继承任何类**，没有虚函数，没有依赖注入的接口。它可以被直接构造在测试函数里：

```cpp
LoginViewModel vm;
check(!vm.can_submit.get(), "空表单不能提交");
```

这就是第 1 章承诺的"业务逻辑可单元测试"的具体样子 —— 不是宣传语，是一个能跑的断言 👌

---

## 2️⃣ 测派生逻辑：把每条分支都走一遍

`hint` 这个 `Computed` 有三层优先级判断：

```cpp
if (attempts.get() >= 3)        return "尝试次数过多";
if (user.get().empty())         return "请输入用户名";
if (password.get().size() < 6)  return "密码至少 6 位";
return "可以提交";
```

对应三个断言，**每条分支都覆盖到**：

```text
   [ok]   空用户名 -> 提示输入用户名
   [ok]   密码太短 -> 提示密码长度
   [ok]   超过次数 -> 优先级最高的提示
```

最后一条特别值得注意：它验证的是**优先级**，不只是"这条规则生效"。把 `attempts` 设为 3 之后，即使 `user` 也是空的，返回的仍是"尝试次数过多" —— 这说明分支顺序正确。

> 💡 这类"派生值"的测试成本极低：改一个输入、读一次 `Computed`、断言字符串。而在界面里手测这三个场景，需要真的去点输入框、改密码、连点三次提交。

---

## 3️⃣ 测行为约定：等值门与退订

除了"算得对不对"，还有一类更微妙的东西：**框架约定是否真的生效**。

```cpp
value = 1;
value = 1;              // 等值写入, 不通知
value = 2;
check(notifications == 2, "等值写入被静默丢弃");
```

三次写入，两次通知 —— 中间那次相同值被吃掉了。**这个断言在保护一个性能约定**：如果哪天有人改坏了等值门，测试会立刻红 ❌

```cpp
sub.release();
value = 3;
check(notifications == 2, "退订后不再收到通知");
```

这条断言保护的是生命周期约定（第 6 章）。它比"代码看起来没问题"可靠得多。

> 💡 一个思路：**把你依赖的框架行为写成断言**。上面两条断言本质上是"契约测试" —— 它固化的是"我认为 Aria 会这样"，一旦不成立就会暴露，而不是变成生产环境里的诡异 bug。

---

## 4️⃣ 测批处理语义

```cpp
aria::batch([&] {
    a = 1;
    a = 2;
    a = 3;
});
check(notifications == 1, "batch 内三次写入只推一次");
```

这条断言验证的是第 5 章的核心承诺。它值钱的场景是**性能回归**：如果哪天 `batch` 失效了，界面上会开始闪中间态，而这种问题在人工测试里很容易被忽略。

---

## 5️⃣ 测异步：`blocking_get` 的适用边界

```cpp
auto task = []() -> Task<int> {
    co_return 6 * 7;
};
check(task().blocking_get() == 42, "协程结果可以被同步取出");
```

⚠️ 注意这里用的是**同步任务体**（`co_return` 直接返回，没有 `schedule_on`）。第 17 章讲过的边界在这里同样成立：

| 任务体 | 测试写法 |
|---|---|
| 同步 | `blocking_get()` 直接取结果 |
| 真异步（含 `schedule_on`） | `start_detached()` + 等待完成信号 |

测试异步代码时还有个好工具：`VirtualTimeExecutor` —— 它用虚拟时钟，可以让"等 3 秒超时"这种用例瞬间跑完，且结果稳定（不受机器负载影响）。Aria 自己的超时测试就是这么写的。

---

## 6️⃣ 框架自带的一致性套件

最后一件事：**你自己的适配器和列表视图，可以用框架的套件验。**

```cpp
#include "aria/binding/testing/adapter_conformance.hpp"   // 适配器一致性
#include "aria/testing/list_conformance.hpp"              // 列表源一致性
```

这两套的意义在于：**它们就是内置实现自己也在跑的同一份测试**。所以你的适配器不是"自己觉得对了"，而是接受了和官方适配器同样的验收标准 ✅

---

## 🧭 测试策略速查

| 测什么 | 怎么写 | 成本 |
|---|---|---|
| 派生逻辑（`Computed`） | 改输入 → 读 `Computed` → 断言 | 极低 |
| 分支覆盖 | 每个分支构造一次输入条件 | 低 |
| 框架约定（等值门、batch、退订） | 计数器 + 断言通知次数 | 低 |
| 异步逻辑 | 同步体用 `blocking_get`；真异步用虚拟时钟 | 中 |
| 自定义适配器/列表源 | 跑框架自带的一致性套件 | 低 |
| 界面外观与交互 | 需要真实 UI 测试 | 高（本教程不覆盖） |

**结论：在 Aria 里，绝大多数逻辑都属于前三行。** 界面层剩下的那部分薄得刚好，值得用人工或 UI 测试去覆盖。

---

## 📌 小结

- 🧪 ViewModel 是纯 C++，**测试不需要窗口、事件循环或 UI 工具包**；
- 🎯 派生逻辑的测试成本极低：改输入、读 `Computed`、断言；
- 🔒 把框架约定（等值门、`batch`、退订）写成断言，它们是契约测试，能抓住性能与生命周期回归；
- ⏱️ 异步测试区分同步体与真异步，虚拟时钟能让超时用例瞬间跑完；
- 📦 自定义适配器与列表源可以跑框架自带的一致性套件，标准与官方实现一致。
