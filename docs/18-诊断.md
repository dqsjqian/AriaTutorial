# 诊断：把响应式图导出来看

响应式系统的老大难问题是**看不见**：值为什么不刷新？依赖关系到底是什么样？谁在触发谁？

Aria 提供了一组诊断接口，可以直接把依赖图**导出成文本、Graphviz、JSON** 🔍

---

## 📄 完整程序

```cpp
// ch18: 诊断 -- 把响应式图导出来看
#include "aria/aria.hpp"
#include "aria/reactive/inspector.hpp"

#include <iostream>
#include <string>
#include <vector>

using namespace aria;
using aria::reactive::GraphInspector;
using aria::reactive::Node;

int main() {
    std::cout << "== 1. 先给节点起名字 ==\n";
    Property<double> price{100.0};
    Property<int>    quantity{2};
    Property<double> discount{0.9};

    price.set_debug_name("price");
    quantity.set_debug_name("quantity");
    discount.set_debug_name("discount");

    Computed<double> subtotal{[&] { return price.get() * quantity.get(); }};
    subtotal.set_debug_name("subtotal");

    Computed<double> total{[&] { return subtotal.get() * discount.get(); }};
    total.set_debug_name("total");

    std::cout << "   total = " << total.get() << '\n';

    std::cout << "\n== 2. to_text: 人类可读的依赖图 ==\n";
    std::cout << GraphInspector::to_text({static_cast<const Node*>(&total)});

    std::cout << "\n== 3. to_dot: 粘进 Graphviz 就能画图 ==\n";
    std::cout << GraphInspector::to_dot({static_cast<const Node*>(&total)}, "invoice");

    std::cout << "\n== 4. to_json: 喂给工具链 ==\n";
    std::cout << GraphInspector::to_json({static_cast<const Node*>(&total)}) << '\n';

    std::cout << "\n== 5. TraceSink: 捕获事件流 ==\n";
    std::vector<TraceEvent> events;
    {
        ScopedTraceSink guard{[&events](const TraceEvent& ev) { events.push_back(ev); }};
        price = 200.0;
        quantity = 3;
    }

    std::cout << "   两次写入共捕获 " << events.size() << " 条事件\n";
    for (const auto& ev : events) {
        std::cout << "   category = " << ev.category_name() << '\n';
    }

    std::cout << "\n== 6. 没起名字的节点会回退成 <Kind>#<id> ==\n";
    Property<int> anonymous{0};
    Computed<int> also_anonymous{[&] { return anonymous.get() + 1; }};
    (void)also_anonymous.get();
    std::cout << GraphInspector::to_text({static_cast<const Node*>(&also_anonymous)});

    return 0;
}
```

## 1️⃣ 第一步永远是起名字

```cpp
price.set_debug_name("price");
```

不设名字也能导出，但输出里会是一串地址：

```text
[Derivation] Derivation#7  depth=1  v=2  state=Clean
[Source] Source#6  depth=0  v=1  state=Clean
```

看第 6 段的输出 —— 未命名节点回退成 `<Kind>#<id>` 格式。所以**调试前先给关键节点起名**，这是一条值得写进团队规范的建议 ✅

---

## 2️⃣ to_text：一屏看懂的依赖图

```text
[Derivation] total  depth=2  v=2  state=Clean
[Derivation] subtotal  depth=1  v=2  state=Clean
[Source] price  depth=0  v=1  state=Clean
```

四个字段各有含义：

| 字段 | 含义 |
|---|---|
| `[Source]` / `[Derivation]` | 节点类型：源（`Property`）还是派生（`Computed`） |
| `depth` | 从起点到这里的距离。`total` 是 2，因为它依赖 `subtotal` 再依赖 `price` |
| `v` | 版本号。值每变化一次加一 |
| `state` | `Clean` 表示当前缓存有效 |

`depth` 特别有用：**它直观反映了依赖链的层数**。如果你看到 `depth=17`，那就是一个值得警惕的深链 —— 每层都会带来重算开销。

注意输出里节点是**从下游往上游列**的（`total` → `subtotal` → 三个 Source），符合"我要排查这个值为什么不对，就顺着它的依赖往上找"的调试直觉。

---

## 3️⃣ to_dot：画出来

```cpp
GraphInspector::to_dot({static_cast<const Node*>(&total)}, "invoice");
```

输出是标准 DOT 格式，直接粘进 [Graphviz Online](https://dreampuf.github.io/GraphvizOnline/) 或本地 `dot -Tpng` 就能出图：

```dot
digraph "invoice" {
  rankdir=LR;
  node [shape=box, style=rounded, fontname="monospace"];
  "900237097920" [label="Derivation\ntotal\nd=2 v=2 Clean", fillcolor="#ffe3b0", ...];
  ...
  "900237097776" -> "900237097920" [label="v=1"];
}
```

注意 `->` 的方向：**从被依赖者指向依赖者**（`discount → total`）。也就是说箭头方向和"数据流动方向"一致 —— 顺着箭头走，就是值传播的路径。

节点颜色由框架按类型区分（`Source` 与 `Derivation` 用不同底色），边的 `label` 带着 observed version，可以用于判断"这条边见过的是哪个版本"。

---

## 4️⃣ to_json：喂给工具链

```json
{"nodes":[{"id":900237097920,"kind":"Derivation","state":"Clean","depth":2,"version":2,"name":"total"}, ...],
 "edges":[{"from":900237097776,"to":900237097920,"observed_version":1}, ...]}
```

JSON 适合被自动化工具消费：你可以写脚本拉取图结构、统计节点数量、检查有没有意料之外的依赖边，甚至把图快照存下来做**回归对比**。

---

## 5️⃣ TraceSink：捕获事件流

`to_*` 系列给的是**图的结构快照**。如果你想看**运行过程中的事件**，用 `TraceSink`：

```cpp
std::vector<TraceEvent> events;
{
    ScopedTraceSink guard{[&events](const TraceEvent& ev) { events.push_back(ev); }};
    price = 200.0;
    quantity = 3;
}
```

`ScopedTraceSink` 是 RAII 的 —— 构造时安装 sink，析构时自动卸载。所以你可以只在关心的代码段里打开它。

输出：

```text
   两次写入共捕获 20 条事件
   category = Reactive
   (共 20 行)
```

两次写入产生了 20 条事件 —— **平均一次写入 10 条**。这个数字值得玩味：它体现了"一次写入会引发一整条链的连锁反应"（`price` 变 → `subtotal` 失效重算 → `total` 失效重算，每一步都有事件）。

事件按类别分组，`TraceEvent::category_name()` 给出的是类别名：

| 类别 | 覆盖范围 |
|---|---|
| `Reactive` | 响应式图的失效与重算 |
| `Async` | 协程与调度 |
| `Binding` | 绑定与派发 |
| `Command` | 命令执行 |
| `Validation` | 校验 |
| `List` | 列表变更 |

真实的排查里，你通常会按类别过滤 —— 比如只关心 `Binding` 类事件，看"为什么这次变化没有推到界面上"。

---

## 🎯 三个接口怎么选

| 你想知道 | 用什么 |
|---|---|
| 依赖关系长什么样 | `GraphInspector::to_text()` |
| 想画出来看 / 存档 | `to_dot()` / `to_json()` |
| 某段代码运行时发生了什么 | `ScopedTraceSink` |
| 这个节点是谁 | 先 `set_debug_name()` |

---

## 📌 小结

- 🏷️ **先给节点起名**（`set_debug_name`），否则输出里全是地址；
- 📄 `to_text()` 给人看：节点类型、深度、版本、状态一目了然；
- 🎨 `to_dot()` 给 Graphviz：箭头方向即数据流动方向；
- 🧰 `to_json()` 给工具链：可做图快照与回归对比；
- 📡 `ScopedTraceSink` 捕获运行期事件流，按类别过滤；
- ⚠️ 节点 id 每次运行都不同，不要把具体数值写进断言。
